# SamboTL — система проведения турниров по самбо

Офлайн-система для автоматизации турниров по самбо. Работает в локальной сети
Windows-машин: один ПК — сервер, остальные подключаются к нему через браузер
(в перспективе — портабельное клиентское приложение с кнопками-лаунчерами).

## Стек

| Слой | Технология |
|------|-----------|
| Бэкенд | Python 3.13, Django 5.1, DRF |
| Админка | **django-unfold** (современная тема, кастомный дашборд) |
| Реалтайм | Django Channels 4 + ASGI (WebSocket, in-memory layer) |
| БД | SQLite — **один файл на турнир** |
| Импорт/отчёты | openpyxl (Excel), python-docx (Word) |
| Раздача статики | WhiteNoise (без внешних CDN — офлайн) |

## Структура

```
config/                 # настройки Django, ASGI/WSGI, WebSocket-маршруты
apps/
  core/                 # утилиты: реестр турниров, импорт Excel, live-шина,
                        # разбор веса, хеширование пароля, management-команды
  tournaments/          # Турнир (настройки, логотипы, тайминги), Этапы
  participants/         # Участник (ФИО раздельно), Клуб, Взвешивание
  competition/          # Возрастные/весовые категории, Ковры, Судьи,
                        # Сетки, Схватки, События схватки
data/
  tournaments.json      # каталог турниров
  active_tournament.json# какой файл БД сейчас обслуживает сервер
  tournaments/*.sqlite3 # по файлу на каждый турнир
scripts/                # генератор примера Excel
```

## Быстрый старт

```powershell
cd c:\projects\samboTL
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 1. Создать турнир (отдельный SQLite-файл, миграции и категории по умолчанию)
.\.venv\Scripts\python.exe manage.py new_tournament "Кубок Москвы 2026" `
    --system olympic --audience adults --mats 3 --password 1234 --activate

# 2. Импорт участников из Excel
.\.venv\Scripts\python.exe manage.py import_participants data\samples\participants_sample.xlsx
#    (сначала можно проверить файл без записи: ... --dry-run)

# 3. Запустить сервер (админка: http://127.0.0.1:8000/admin/)
.\.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000
```

Для LAN: запустите `runserver 0.0.0.0:8000`, клиенты открывают
`http://<IP-сервера>:8000/`.

## Модель хранения: «файл на турнир»

- Каждый турнир — отдельный файл `data/tournaments/<slug>.sqlite3`.
- `data/tournaments.json` — каталог, `data/active_tournament.json` — активный.
- Перенос турнира = копирование одного `.sqlite3` файла.

Команды:

```powershell
manage.py new_tournament <название> [--system olympic|six_errors] [--audience adults|children|mixed] [--mats N] [--password P] [--activate]
manage.py list_tournaments [--activate <slug>]
manage.py import_participants <файл.xlsx> [--dry-run]
```

## Импорт из Excel

- **ФИО обязательно отдельными колонками**: `Фамилия`, `Имя`, `Отчество`.
- Категория определяется так:
  1. если в колонке «Категория» есть число («до 90», «90 кг») — парсится
     верхняя граница и ищется категория «до 90 кг»;
  2. если категория пуста — автоопределение по «Текущему весу»
     (запасной вариант — «Заявленный вес»).
- Поддерживаются синонимы заголовков (RU/EN), предпросмотр через `--dry-run`.

## Live-обновления (WebSocket)

Все экраны подписаны на одну шину `ws/live/` (группа `tournament_live`).
Сейчас из админки автоматически транслируются:
- прогресс взвешивания (`weighing.progress`) — «сколько прошло / сколько осталось»;
- состояние схватки (`bout.updated`).

Достаточно вызвать `apps.core.live.broadcast({...})` из любого места кода.

## REST API

Клиентские экраны общаются с сервером по JSON. Аутентификация — пароль турнира
в заголовке `Authorization: Token <пароль>` (или вход в админку). Корень `/api/`.

| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| GET | `/api/health/` | Проверка доступности сервера |
| GET | `/api/participants/` | Список участников (`?search=` — поиск по ФИО/клубу) |
| GET | `/api/weigh-ins/` | Все записи взвешивания |
| POST | `/api/weigh-ins/` | Внести результат взвешивания (`participant_id`, `current_weight`, `passed`, `weighed_by`) |
| GET | `/api/weigh-ins/progress/` | Прогресс взвешивания (всего / прошло / осталось) |
| GET | `/api/brackets/` | Список сеток |
| POST | `/api/brackets/setup/` | Создать сетки для всех непустых категорий |
| POST | `/api/brackets/{id}/preview/` | Предпросмотр сетки (`strategy`: `random`/`seeded`/`mixed`) |
| POST | `/api/brackets/{id}/generate/` | Провести жеребьёвку и создать схватки |
| POST | `/api/brackets/{id}/approve/` | Утвердить сетку |
| GET | `/api/mats/` | Ковры |
| POST | `/api/mats/schedule/` | Распределить схватки по коврам (без простоя) |
| GET | `/api/bouts/?program=1` | Компактная программа для табло/расписания |
| GET/PATCH | `/api/bouts/{id}/` | Схватка (счёт, статус, победитель) |

Сквозная проверка всех этапов: `python scripts/smoke_api.py`.

## Клиентские экраны (SPA)

Каталог `frontend/` — Vue 3 + Vite. Собирается в **локальный бандл** (без CDN)
в `static/spa/`, сервер раздаёт его по адресу `/app/`.

```powershell
cd frontend
npm install
npm run build          # → ../static/spa/
```

Открыть: `http://<IP-сервера>:8000/app/` → ввести пароль турнира.

Экраны:
- `/app/` — вход по паролю доступа;
- `/app/home` — выбор роли (взвешивание / жеребьёвка / судейство / табло / расписание);
- `/app/weighing` — взвешивание: поиск, текущий вес, «прошёл/не прошёл»,
  прогресс в реальном времени (WebSocket);
- `/app/draw` — жеребьёвка: создание сеток, стратегия (случайная/посев/смешанная),
  предпросмотр и генерация, распределение по коврам;
- `/app/referee` — судейство: выбор ковра, очередь схваток, очки (+1/+2/+4),
  замечания, победитель;
- `/app/scoreboard` — табло для ТВ (второй экран): таймер схватки с обратным
  отсчётом, счёт, подсветка победителя, «кто готовится» снизу;
- `/app/schedule` — расписание: очередь схваток по коврам с анимациями и
  живым обновлением статусов (WebSocket);
- `/app/reports` — отчёты: скачивание протоколов в Word/Excel.

## Отчёты (Word / Excel)

Генерация через `openpyxl` (Excel) и `python-docx` (Word), модуль `apps/core/reports.py`.

| Маршрут | Формат | Назначение |
|---------|--------|-----------|
| `/api/reports/weighing.xlsx` | Excel | Протокол взвешивания (ФИО, клуб, категория, заявленный/текущий вес, результат) |
| `/api/reports/bracket/{id}.xlsx` | Excel | Сетка категории (пары первого круга) |
| `/api/reports/results.docx` | Word | Итоговый протокол (завершённые схватки по категориям, счёт, победители) |

Проверка генерации: `python scripts/gen_reports.py` и `python scripts/verify_reports.py`.

Управление схваткой через API: `POST /api/bouts/{id}/start|score|warning|finish`.
Изменения мгновенно транслируются всем экранам по WebSocket (`bout.updated`).

Проверка сборки и раздачи: `python scripts/check_spa.py`.

## Упаковка (Windows)

**Подробная инструкция для организаторов: [`docs/INSTALL.md`](docs/INSTALL.md).**

Сборка обоих `.exe` одной командой:

```powershell
.\packaging\build.ps1
```

Скрипт делает: сборку Vue SPA → `collectstatic` → PyInstaller для сервера и клиента,
создаёт ярлыки на рабочем столе, а при наличии Inno Setup — и установщик клиента.

Результат:

| Файл | Назначение |
|------|-----------|
| `dist\SamboTLServer.exe` | Сервер **с визуальной панелью** (запуск/остановка, список турниров, создание турнира, показ паролей) |
| `dist\SamboTLClient.exe` | Портабельный клиент (pywebview): адрес сервера + пароль, кнопки экранов |
| `dist\installer\SamboTLClientSetup.exe` | Установщик клиента (Inno Setup) |

### Панель сервера

`SamboTLServer.exe` без аргументов открывает **окно-панель**, где видно и понятно:

- индикатор запущен/остановлен, порт и адрес приёма;
- кнопки «Запустить сервер» / «Остановить» / «Открыть экраны» / «Открыть админку»;
- список турниров (клик = сделать активным), «Новый турнир»;
- после запуска — **адрес для клиентов, пароль экранов, логин/пароль админки**;
- блок «Доступ» — показать и сменить пароли активного турнира.

Служебные подрежимы (для автоматизации/отладки):

```powershell
SamboTLServer.exe --console             # headless: daphne + авто-открытие браузера
SamboTLServer.exe --list-tournaments    # JSON-список турниров
SamboTLServer.exe --create-tournament '{"name":"...","system":"olympic","audience":"adults","mats":4,"password":"1234","admin_password":"admin1234"}'
SamboTLServer.exe --select <slug>       # выбрать активный турнир
SamboTLServer.exe --run <port>          # просто поднять сервер
SamboTLServer.exe --set-access-password <slug> --value <new>
SamboTLServer.exe --set-admin-password <slug> --value <new>
```

### Сервер

Запускается двойным щелчком (или с ярлыка). Параметры:

```powershell
SamboTLServer.exe [--port 8000] [--host 0.0.0.0] [--no-browser]
```

- Данные (`data\tournaments\*.sqlite3`, медиа, бэкапы) создаются **рядом с .exe** —
  папку `dist` можно целиком скопировать на флешку и перенести.
- Статические файлы и SPA упакованы внутрь `.exe` (WhiteNoise).
- Клиенты в локальной сети открывают `http://<IP-сервера>:8000/app/`.

### Клиент

Портабельный, без установки. Оператор вводит адрес сервера и пароль турнира один раз,
далее кнопки: взвешивание, жеребьёвка, судейство, табло, расписание, отчёты, админка.

> Требование: WebView2 Runtime (на Windows 10/11 обычно уже установлен; на старых
> системах — установить «Microsoft Edge WebView2 Runtime»).

### Зависимости сборки

```powershell
pip install -r requirements-build.txt   # pyinstaller + pywebview
```

### Нюансы frozen-сборки (уже учтены)

- `config/settings.py` различает `BUNDLE_DIR` (внутри `.exe`) и `BASE_DIR` (рядом с `.exe`) —
  база и медиа всегда в записываемой папке.
- `AUTOBAHN_USE_NVX=0` — отключает нативные расширения autobahn (нужны C-исходники в рантайме).
- `collect_submodules` в spec-файлах подхватывает Django-приложения, загружаемые по строке.

## Упаковка (вручную, без скрипта)

```powershell
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe -m PyInstaller launcher\server.spec --noconfirm
.\.venv\Scripts\python.exe -m PyInstaller launcher\client.spec --noconfirm
```

Сервер также можно запустить в режиме разработки через daphne:

```powershell
.\.venv\Scripts\daphne.exe -b 0.0.0.0 -p 8000 config.asgi:application
```
